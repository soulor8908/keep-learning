# 物料分包优化方案

## 背景

当前每个技术栈（vue2/vue3/h5）的所有物料打成一个 UMD 文件（如 `vue3-widgets.js`），加载任意物料需全量下载整个包。目标是**每个物料独立一个 UMD 文件**，host 按需加载。

## 现状分析

每个 widget 目录下已有独立的 `index.js` 入口，只是构建时未被使用：

```
vue3-widgets/src/widgets/
├── finance-panel/index.js   ← 已有独立入口，调用 createVue3Widget
├── user-panel/index.js      ← 已有独立入口
```

当前只用 `src/index.js` 统一导出所有物料，Vite 单入口构建。

## 改动方案

### 1. 修改 Vite 构建配置（三个 widget 包各改一次）

**文件**: `demo/vue3-widgets/vite.config.js`、`demo/vue2-widgets/vite.config.js`、`demo/h5-widgets/vite.config.js`

Vite lib mode 的 UMD 格式不支持多入口，改为**每个物料单独一次 `build()` 调用**。把 `vite.config.js` 改为构建脚本，扫描 `src/widgets/*/index.js` 作为入口：

```js
// vue3-widgets/vite.config.js 改为:
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { resolve } from 'path';
import fs from 'fs';

// 扫描 src/widgets/ 下所有子目录的 index.js
const widgetsDir = resolve(__dirname, 'src/widgets');
const entries = fs.readdirSync(widgetsDir)
  .filter(f => fs.statSync(resolve(widgetsDir, f)).isDirectory())
  .reduce((acc, name) => {
    acc[name] = resolve(widgetsDir, name, 'index.js');
    return acc;
  }, {});

export default defineConfig({
  plugins: [vue()],
  build: {
    lib: {
      entry: entries,  // 多入口
      formats: ['umd'],
      fileName: (format, entryName) => `${entryName}.js`,
    },
    rollupOptions: {
      external: (id) => {
        if (id.endsWith('.css')) return false;
        return id === 'vue' || id === 'element-plus';
      },
      output: {
        globals: { vue: 'Vue3', 'element-plus': 'ElementPlus' },
      },
    },
  },
});
```

> **注意**: Rollup UMD 格式实际不支持多入口。需改为**构建脚本模式**——写一个 `build.mjs` 脚本循环调用 `vite build`，每个物料独立构建。

实际方案：在每个 widget 包下新增 `build.mjs` 构建脚本：

```js
// demo/vue3-widgets/build.mjs
import { build } from 'vite';
import vue from '@vitejs/plugin-vue';
import { resolve, dirname } from 'path';
import { fileURLToPath } from 'url';
import fs from 'fs';

const __dirname = dirname(fileURLToPath(import.meta.url));
const widgetsDir = resolve(__dirname, 'src/widgets');

const widgets = fs.readdirSync(widgetsDir)
  .filter(f => fs.statSync(resolve(widgetsDir, f)).isDirectory());

for (const name of widgets) {
  await build({
    plugins: [vue()],
    build: {
      lib: {
        entry: resolve(widgetsDir, name, 'index.js'),
        name,  // window[name]
        formats: ['umd'],
        fileName: () => `${name}.js`,
      },
      rollupOptions: {
        external: (id) => {
          if (id.endsWith('.css')) return false;
          return id === 'vue' || id === 'element-plus';
        },
        output: {
          globals: { vue: 'Vue3', 'element-plus': 'ElementPlus' },
        },
      },
      outDir: resolve(__dirname, 'dist'),
      emptyOutDir: false,
    },
  });
  console.log(`  built: ${name}.js`);
}
```

vue2-widgets 类似，替换 plugin 和 globals：
- plugin: `@vitejs/plugin-vue2`
- external: `vue`, `element-ui`
- globals: `{ vue: 'Vue2', 'element-ui': 'ELEMENT' }`

h5-widgets 更简单，无需 plugin 和 external。

### 2. 更新各 widget 包的 package.json

**文件**: `demo/vue3-widgets/package.json`、`demo/vue2-widgets/package.json`、`demo/h5-widgets/package.json`

```json
{
  "scripts": {
    "build": "node build.mjs",
    "watch": "node build.mjs --watch"
  }
}
```

### 3. 删除旧的统一入口

**删除/清空**: `demo/vue3-widgets/src/index.js`、`demo/vue2-widgets/src/index.js`、`demo/h5-widgets/src/index.js`

改为仅导出物料清单（供非分包场景兼容），或直接删除。推荐保留但改为 re-export：

```js
// src/index.js - 兼容用途，分包构建不使用此文件
export { default as biFinancePanel } from './widgets/finance-panel/index.js';
export { default as biUserPanel } from './widgets/user-panel/index.js';
```

### 4. 更新 Host 注册表

**文件**: `demo/host/src/App.vue`

```js
// 之前: 指向聚合文件
biFinancePanel: { name: 'biFinancePanel', js: '/widgets/vue3-widgets.js', vueVersion: '3' },

// 之后: 指向独立文件
biFinancePanel: { name: 'biFinancePanel', js: '/widgets/finance-panel.js', vueVersion: '3' },
biUserPanel:    { name: 'biUserPanel',    js: '/widgets/user-panel.js',    vueVersion: '3' },
```

### 5. 更新 Host Vite 插件的文件发现

**文件**: `demo/host/vite.config.js`

`localServePlugin` 已自动扫描 `dist/` 目录下所有 `.js` 文件，**无需修改**。分包后 `dist/` 下从 1 个文件变成 N 个文件，插件会自动发现。

### 6. 更新部署脚本

**文件**: `scripts/deploy_build.sh`

当前脚本有硬编码的旧路径（`demo/vue2-widget/dist/widget.js`），需更新为通配符拷贝：

```bash
# 旧: 硬编码单文件
cp demo/vue2-widget/dist/widget.js demo/host/dist/widgets/vue2-sales-panel.js

# 新: 通配符拷贝所有产物
for dir in vue2-widgets vue3-widgets h5-widgets; do
  cp demo/$dir/dist/*.js demo/host/dist/widgets/ 2>/dev/null || true
  cp demo/$dir/dist/*.css demo/host/dist/widgets/ 2>/dev/null || true
done
```

### 7. 更新根 package.json 的 dev 脚本

**文件**: `package.json`

`watch` 命令需要适配新的构建脚本：

```json
"dev": "pnpm build:widgets && concurrently \"pnpm -r --filter vue2-widgets --filter vue3-widgets --filter h5-widgets run watch\" \"pnpm --filter host serve\""
```

watch 命令不变，因为 `build.mjs` 需要支持 `--watch` 参数（使用 vite 的 `watch` 模式或 chokidar）。

## 产物对比

| 场景 | 之前 | 之后 |
|------|------|------|
| vue3-widgets dist/ | `vue3-widgets.js` (1 文件) | `finance-panel.js` + `user-panel.js` (N 文件) |
| 加载 biFinancePanel | 下载整个 vue3-widgets.js | 只下载 finance-panel.js |
| 新增物料 | 修改 src/index.js | 新建 widgets/xxx/index.js，自动被构建脚本发现 |

## 验证方式

1. `pnpm build:widgets` — 确认每个 widget 包 dist/ 下产出多个独立 JS 文件
2. `pnpm dev` — 浏览器打开 localhost:5000，确认所有物料正常加载
3. Chrome DevTools Network 面板 — 确认加载某个物料时只请求对应的 JS 文件
4. 新增一个测试物料到 vue3-widgets/src/widgets/ 下，重新 build 确认自动被发现
